Найти трейс `tracing_verification`/`process_analysis`, показать вложенность узлов, run `ChatOpenAI` с токенами, `rag.search_automation_patterns`, `mcp.*`.

## Демонстрация (2:00–6:00)

**Шаг 1 — PDF (≈1:30).** Страница «Распознавание процесса» → `samples/demo_process.pdf` → «Распознать процесс». Показать таблицу: 8 операций, у части нет участника/длительности — **они пустые, а не выдуманные**. Исправить одну ячейку, показать, что схема AS-IS перерисовалась → «Подтвердить».

**Шаг 2 — анализ (≈1:30).** Страница «AI-анализ» → указать число запусков (допущение) → «Запустить AI-анализ». Показать исходные метрики, проблемы, найденные паттерны (с идентификаторами и разделами), таблицу рекомендаций. Отметить: **workflow приостановлен** — это `interrupt()` в LangGraph.

**Шаг 3 — решение пользователя и TO-BE (≈1:00).** Выбрать рекомендацию, задать допущение о длительности после автоматизации (если LLM не предложила) → «Сформировать TO-BE и отчёт». Показать: схемы AS-IS/TO-BE, сравнение показателей с пометкой «модельная оценка», скачать Markdown-отчёт (**скачивание — только с вашего согласия на демонстрационной машине**).

**Шаг 4 — PNG (≈0:30, по времени).** Показать, что тот же путь работает для `samples/demo_process.png` через Vision. **Честно**: связи на схеме Vision может прочитать как ветвление, — система выводит предупреждение.

**Если сеть или API недоступны:** показать, что приложение отвечает понятной ошибкой с инструкцией, а не имитирует результат; перейти к заготовленному отчёту `data/analysis_report_demo.md`.

## Бизнес-ценность (5% оценки)

- **Пользователь одним предложением:** бизнес-аналитик или владелец процесса в компании, у которого есть регламент (PDF) или схема (картинка) и который должен быстро понять, что в процессе стоит автоматизировать и что это даст.
- **Боль и как решают сейчас:** аналитик вручную выписывает операции, считает время, ищет подходящие способы автоматизации и оценивает эффект «на глаз» — долго, неповторяемо, цифры часто ничем не подкреплены. ProcessMind превращает документ в структуру, считает метрики детерминированно, предлагает способы автоматизации со ссылкой на паттерн и условия применимости, а эффект считает только по допущениям, которые задаёт сам пользователь.

- **Что должно произойти для развития после курса:** _[заполнить автору]_. Обоснованные технические шаги из ограничений проекта: проверка на реальных (обезличенных) процессах, персистентное состояние, сравнение моделей, улучшение чтения связей на схемах.

### Архитектура и техническое решение

| Вопрос | Ответ |
|---|---|
| Почему LangGraph, какие альтернативы? | Нужны условные переходы, сохраняемое состояние и нативная пауза `interrupt()` для подтверждения человеком; поток линейный, поэтому многоагентная схема избыточна. **CrewAI и Parlant не пробовались** — сравнение с ними не проводилось, выбор основан на требованиях (пауза и условные рёбра) и знакомом API |
| Поток управления, ветвления, циклы, HITL? | 8 узлов. Условные рёбра после узлов 1–5: `invalid` / `failed` / `no_recommendations` / `no_selection` ведут сразу в `generate_report`. HITL — `human_approval` (`interrupt`). Цикл: при некорректном решении пользователя узел повторно выдаёт `interrupt` с текстом ошибки |
| Путь одного запроса? | Схема и последовательность — [ARCHITECTURE.md](ARCHITECTURE.md) §1 и §3: загрузка → извлечение → подтверждение → граф → пауза → решение → симуляция MCP → отчёт |
| Что независимо и заменяемо, где сознательный coupling? | Заменяемы: MCP-сервер (стандартный протокол), база знаний (Markdown + индекс), Skill (файл). Осознанный coupling: вызовы LLM завязаны на OpenAI Structured Outputs и Vision в одном модуле `processmind/parsing/llm.py` — смена провайдера потребует переписать этот модуль |
| Почему эта LLM, баланс стоимости/скорости/качества, стоимость запроса? | [MODEL_CHOICE.md](MODEL_CHOICE.md): gpt-4o-mini, ≈ $0.0016 за анализ с RAG (арифметика по измеренным токенам), 7.18 с сквозная латентность; другие модели не сравнивались |
| Если LLM недоступна или подорожает? | Реализовано: понятная ошибка, исход `failed`, без имитации. **Fallback на другую модель, бюджетные лимиты и кэш не реализованы** — план описан в MODEL_CHOICE.md §4 |
| Осознанные trade-off? | RAG: +2.94 с и +2007 токенов ради прослеживаемости, а не точности; один граф вместо агентов — проще и предсказуемее, но без самопланирования; `MemorySaver` — просто, но состояние в памяти процесса; temperature 0.0 — воспроизводимость важнее прироста F1 на малой выборке |
| Гипотезы, которые не подтвердились? | (1) «RAG повысит точность рекомендаций» — F1 0.725 (без RAG) против 0.710 (с RAG), разница в пределах шума. (2) «Паттерны помогут не предлагать лишнего» — на отрицательных примерах с RAG хуже (1/4 против 3/4, n=4). (3) «Vision точно прочитает схему» — связи прочитаны как ветвление, тип операции нестабилен |

### Качество LLM-инженерии

| Вопрос | Ответ |
|---|---|
| Эволюция главного промпта, v1 и текущая? | **Истории версий нет.** Главный промпт — `SKILL.md`; в git у него одна версия (коммит добавления), предыдущие варианты не сохранялись. Выдумывать «v1» нельзя; можно показать текущий Skill, его структуру и то, что sha256 версии фиксируется в каждом отчёте и в EVALS.md |
| Что в golden dataset и почему эти примеры? | 30 синтетических: 23 positive в 7 категориях (выявление ручных операций, применимость, маршрутизация, валидация, дедупликация, уведомления, прочие паттерны), 4 negative («автоматизация не нужна»), 3 ambiguous. Краевые случаи — negative и ambiguous. Оговорка: написан одним автором вместе с базой знаний, метрики вероятно оптимистичны |
| Какие метрики и чего они НЕ показывают? | Hit@3 (поиск), Recommendation F1 (по множествам паттернов), доля корректных negative, latency, токены. Не показывают: правдивость обоснований (проверяется только наличие текста), качество на реальных процессах, значимость различий (выборка мала, доверительные интервалы не считались). LLM-as-judge не используется |
| A/B: гипотеза, результат, решение? | Гипотеза: RAG повышает качество рекомендаций. Результат: прироста F1 нет, зато 100% рекомендаций со ссылкой на паттерн и условиями применимости; цена — токены и задержка. Решение: рабочая конфигурация — с RAG ради прослеживаемости (обосновано в MODEL_CHOICE.md) |
| Как устроен RAG, альтернативы? | [ARCHITECTURE.md](ARCHITECTURE.md) §6: chunking по смысловым разделам паттерна, `text-embedding-3-small`, ChromaDB (cosine), Top-3. **Reranker не используется; альтернативные chunking-стратегии, embedding-модели и базы не сравнивались** |
| Какие edge cases ломают систему? | Найдены аудитом и оценками: связи на схемах-изображениях (ветвление вместо перехода); нестабильный тип операции на изображении; LLM не всегда предлагает длительность после автоматизации; лишние рекомендации на negative-примерах с RAG; не-словарный процесс на входе (исправлено, есть тест) |

### Полнота обязательных модулей

| Вопрос | Ответ |
|---|---|
| MCP-сервер: почему эти tool'ы и почему MCP, а не API? | `validate_process`, `calculate_process_metrics`, `simulate_automation` — детерминированные расчёты, которые нельзя доверять LLM. MCP: стандартный протокол вызова, отдельный процесс, те же инструменты доступны любому MCP-клиенту, легко тестируются. Обычный HTTP API дал бы то же, но без стандартного описания инструментов для LLM-агентов |
| Skill: содержимое, триггеры, чем полезнее промпта? | `.claude/skills/process-analysis/SKILL.md`: описание с условиями применения, раздел «Когда применять (триггеры)», методика, правила выявления ручных операций и выбора паттернов, требования к обоснованию, запрет выдумывать факты, правила модельных оценок. Один файл работает и как Skill Claude Code, и как системный промпт LLM-узла — методика версионируется отдельно от кода, её версия фиксируется в отчёте |
| Мультимодальность: зачем, что потеряно без неё? | Vision читает процессы, нарисованные как схемы. Без неё пользователь с картинкой вместо регламента остался бы без анализа. Ограничение: результат вероятностный — связи и типы операций нужно проверять |
| Дашборд LangSmith с реальными трейсами? | Показать живьём (см. чек-лист подготовки): проект `processmind-ai`, трейс одного анализа демо-процесса. Инструкция по элементам трейса — README, «Мониторинг: LangSmith» |
